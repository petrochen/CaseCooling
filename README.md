# CaseCooling для X570 I AORUS PRO WIFI

CaseCooling управляет радиатором и нижним вдувом компактного ПК по температурам CPU, GPU и жидкости. Панель Windows показывает температуры, загрузку, обороты и уровень шума за последние 24 часа. Кривые откалиброваны для Gigabyte X570 I AORUS PRO WIFI, Ryzen 9 3950X, Radeon RX 480 и NZXT Kraken X с USB ID `1e71:2007`. Перед включением управления сверьте назначение разъёмов своей платы с таблицей ниже.

## Быстрый старт

Для сборки нужны Windows x64, .NET Framework 4.8 и Visual Studio Build Tools с компонентами MSVC x64 и Windows SDK. Из PowerShell обычного пользователя выполните

```powershell
git clone https://github.com/petrochen/CaseCooling.git
cd CaseCooling
.\build.ps1
.\test.ps1
```

Скрипт сборки загружает зафиксированную версию библиотек, проверяет SHA-256 и помещает программы в `bin`. Самотест проверяет логику регулятора и суточную историю на искусственных данных. Для чтения реальных датчиков платы нужен установленный драйвер PawnIO, для GPU — драйвер AMD. Начните с режима наблюдения перед включением службы управления.

## Панель и суточная история

Чтобы открывать графики из области уведомлений, после установки монитора запустите `.\install-tray.ps1` из своей обычной учётной записи. Скрипт добавляет зелёный значок вентилятора в трей и ярлык в автозагрузку пользователя. Один щелчок открывает панель или выводит уже открытое окно на передний план. При закрытии окна значок остаётся доступен.

Запустите `CaseCooling.Monitor.exe` из установленной папки `C:\Program Files\CaseCooling` или из `bin`. Окну нужны только права обычного пользователя. В «Обзоре» температура, загрузка CPU и GPU и обороты показаны на четырёх графиках с общей шкалой времени. Для CPU и GPU линия показывает среднюю загрузку за подписанный интервал, а светлые штрихи — минимум и максимум. Серый фон отмечает периоды без записей. Наведите курсор, чтобы сопоставить температуру, загрузку и обороты в один момент. Отдельные вкладки позволяют скрывать линии нажатием на легенду. Интервалы — от минуты до суток. «Тест CPU + GPU» открывает сохранённый лабораторный прогон, если такой архив есть на компьютере.

Служба `CaseCoolingHistory` запускается автоматически при включении Windows, опрашивает датчики независимо от окна и владельца вентиляторов, пишет одну запись в секунду. CPU и тахометры платы опрашиваются раздельно. Загрузка CPU — по системным счётчикам Windows, GPU — по AMD ADL. Уровень StreamCam записывается в dBFS по энергии отсчётов, аудио в истории отсутствует. Если источник не дал нового значения, в его ряду остаётся пропуск. Карточка может показать последнее измерение возрастом до трёх секунд с отметкой о задержке. Суточный график сохраняет минимумы и максимумы внутри каждого экранного пикселя.

В `history-1s.bin` рядом с установленной службой 86 400 мест, файл занимает 8 640 016 байт. По истечении суток слот перезаписывается. После сна, перерыва записи или изменения часов служба очищает устаревшие слоты. Панель ограничивает выборку по UTC и подписывает шкалу местным временем. При первой установке программа импортирует доступные замеры за последние сутки с их исходными временными отметками. Сохранённые вручную прогоны и исходные CSV старого логгера — отдельные файлы.

Для Ryzen 9 3950X регистратор через публичный модуль PawnIO библиотеки LibreHardwareMonitor читает Tctl/Tdie, температуры CCD и счётчик энергии пакета. Доступ к датчикам сериализован общим мьютексом PCI. Формулы сверены с [реализацией для Family 17h в используемой версии библиотеки](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/995b95062745c6ad18d2a55844b32e5391ca5fd1/LibreHardwareMonitorLib/Hardware/Cpu/Amd17Cpu.cs).

Для установки с нуля запустите `.\install.ps1`, затем `.\install-history.ps1` из повышенного PowerShell. Второй скрипт также обновляет установленную панель и службу записи. Сервис управления вентиляторами и сервис истории запускаются независимо.

## Наблюдение

Из PowerShell в каталоге программы

```powershell
.\bin\CaseCooling.exe self-test
.\bin\CaseCooling.exe observe 10
```

Для показаний CPU и материнской платы запустите PowerShell от администратора. Без аргументов программа делает пять опросов в режиме наблюдения. Необязательный третий аргумент после `observe N` (путь к новому файлу) сохраняет CSV. Поля `*_pwm` показывают считанную команду платы, `*_request` — расчёт регулятора. Обороты записываются отдельно в `*_rpm`. Код завершения 3 означает, что ни одного полного набора обязательных показаний получить не удалось.

## Управление

| Канал | Действие |
|---|---|
| IT8688E 0, радиатор | Кривая по жидкости, 78% от 40 до 44,9 °C, 88% при 45 °C. Возврат с верхней ступени при 44,4 °C. CPU или CCD от 85 °C также запрашивает минимум 88%. |
| IT8688E 1, нижний вдув | Максимум запросов по CPU Tctl/Tdie и GPU. Измеренная точка 55% соответствует примерно 1230 об/мин. |
| IT8688E 2, малый вентилятор | 35% в рабочем режиме. |
| Помпа Kraken | Служба загружает аппаратную кривую от 55% при 33 °C до 100% при 42 °C. При переподключении или паузе опроса свыше 10 секунд кривая загружается повторно. |

Рост команды немедленный. Для снижения PWM условие должно сохраняться 14 секунд. Вентилятор самой RX 480 управляется видеокартой, вентилятор БП — блоком питания.

Отсутствие обязательной температуры или тахометра, остановка помпы либо перегрев переводят три канала платы на 100%. Порог CPU или любого доступного CCD — 87 °C, GPU — 82 °C, жидкости — 47 °C, доступного SSD — 65 °C. Это пороги данного регулятора. Обороты и прочитанный PWM служат разными проверками. Команда на 100% не может компенсировать механическую остановку помпы или вентилятора.

## Проверка прямого PWM на холостом ходу

После штатного выхода из Fan Control команда `.\bin\CaseCooling.exe intake-test` в повышенном PowerShell кратко повышает нижний вдув. Если плата остановила малый вентилятор, проба сначала запускает его на измеренных 35%, проверяет тахометр и освобождает этот канал при выходе. Успех требует роста тахометра вдува более чем на 100 об/мин в трёх последовательных отсчётах, освобождения канала тем же экземпляром драйвера и приближения оборотов к исходным. При работающем Fan Control или NZXT CAM тест отказывается брать управление. Код 20 означает конфликт владельцев.

Команда `.\bin\CaseCooling.exe idle-fault-test` берёт три канала и помпу на холостом ходу. После трёх подтверждений PWM надзорный процесс принудительно завершает рабочий и запускает аварийный. Для успешного результата требуются три отсчёта с PWM 100% и фактическими оборотами не ниже 1900, 1600 и 3500 для радиатора, вдува и малого вентилятора соответственно. После теста плата остаётся на полном обдуве до запуска рабочего регулятора или прежнего профиля.

## Служба

Скрипт `.\install.ps1` в повышенном PowerShell копирует программу в `%ProgramFiles%\CaseCooling`, регистрирует службу с ручным запуском и задаёт перезапуск через диспетчер служб Windows после аварийного завершения. Для контролируемого прогона после выхода из Fan Control используется `Start-Service CaseCooling`. Журнал `service.log` и одна предыдущая копия находятся в каталоге установки. Для остановки используется `Stop-Service CaseCooling`. Для постоянного использования после приёмки можно выбрать автоматический запуск службы и выключить задачу входа Fan Control, чтобы на плату писал один процесс.

Дочерний процесс пишет PWM. Служба следит за завершением каждого опроса. Таймер учитывает только время бодрствования Windows. При исчезновении процесса или паузе более 18 секунд она завершает зависший экземпляр и запускает отдельный режим полного обдува. В этом режиме используются только плата и PawnIO. Аварийный режим после отказа процесса сохраняется до перезапуска службы. При штатной остановке рабочий процесс выставляет 100% на трёх каналах платы и проверяет PWM по обратному чтению. Режим помпы остаётся в Kraken до потери питания. Для возврата к прежним акустическим настройкам достаточно после остановки службы запустить Fan Control с сохранённым профилем.

Полное зависание Windows также останавливает программный надзор. Поведение платы при холодной загрузке, аварийном завершении службы и длительной нагрузке относится к натурным испытаниям. Самотест имитирует сбой рабочего процесса без доступа к PWM.

## Сторонние компоненты

Скрипт берёт LibreHardwareMonitor и его зависимости из [дистрибутива Fan Control V281](https://github.com/Rem0o/FanControl.Releases/releases/tag/V281) и сохраняет уведомления поставщика в `bin/third-party-notices.txt`. Для повседневной работы службы используются эти библиотеки. Формат USB-отчётов Kraken сверялся с [драйвером liquidctl](https://github.com/liquidctl/liquidctl/blob/main/liquidctl/driver/kraken3.py). Панель использует шрифт Source Sans 3 по [лицензии SIL Open Font License](assets/Fonts/LICENSE.md).
